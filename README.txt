PIN নিরাপত্তা ফিক্স — আপলোড নির্দেশনা
====================================

সমস্যা কী ছিল
--------------
আগে প্রতিটি ছাত্রের ৪-সংখ্যার PIN "students" কালেকশনের ডকুমেন্টে সরাসরি
plaintext আকারে থাকত। কিন্তু "students" কালেকশন যেকোনো signed-in ইউজার
(টিচার অথবা যেকোনো অ্যানোনিমাস স্টুডেন্ট সেশন) পড়তে পারত — অর্থাৎ
টেকনিক্যালি যে কেউ Firestore API সরাসরি কল করে সব ছাত্রের PIN পড়ে ফেলতে
পারত।

কী পরিবর্তন করা হয়েছে
----------------------
1. PIN আর কখনো "students" ডকুমেন্টে থাকবে না। এখন থাকে আলাদা
   "student_pins/{studentId}" কালেকশনে, যেটা Firestore rules-এ
   `allow read: if false` — অর্থাৎ কোনো ক্লায়েন্ট (এমনকি ছাত্র নিজেও)
   এটা সরাসরি কখনো read করতে পারবে না।
2. "students" ডকুমেন্টে এখন শুধু `hasPinSet: true/false` ফ্ল্যাগ থাকে
   (PIN সেট আছে কিনা তা দেখানোর জন্য, PIN-এর মান নয়)।
3. ছাত্র লগইন করার সময় এন্টার করা PIN client-এ যাচাই না করে সরাসরি
   "sessions" ডকুমেন্টে লেখা হয়; Firestore rules ভিতরে ভিতরে (get())
   সেটা student_pins-এর সাথে মিলিয়ে দেখে — না মিললে পুরো write-ই
   ব্যর্থ হয় ("permission-denied"), অ্যাপ তখন "ভুল PIN দিয়েছেন" দেখায়।
4. পুরনো ছাত্রদের PIN (যাদের এখনো সরাসরি students ডকুমেন্টে PIN আছে)
   টিচার পরের বার লগইন করার সাথে সাথেই অটোমেটিক migrate হয়ে যাবে —
   কোনো ম্যানুয়াল কাজ লাগবে না।

আপলোড করার ধাপ (আগের মতোই)
----------------------------
১. আপনার GitHub রিপোতে গিয়ে app.js ফাইলটি এই zip-এর app.js দিয়ে
   প্রতিস্থাপন করুন এবং commit করুন। (বাকি সব ফাইল — index.html,
   style.css, firebase-config.js, manifest.json, service-worker.js,
   icon-192.png, icon-512.png — অপরিবর্তিত থাকবে, সেগুলো ছোঁয়ার
   দরকার নেই।)

২. Firebase Console-এ গিয়ে Firestore Database > Rules ট্যাবে যান,
   এই zip-এর firestore.rules ফাইলের পুরো কন্টেন্ট কপি-পেস্ট করে
   "Publish" চাপুন।

৩. সাইট রিফ্রেশ করে টিচার হিসেবে লগইন করুন — এতে পুরনো PIN-গুলো
   অটোমেটিক migrate হয়ে যাবে। এরপর একজন ছাত্রকে দিয়ে তার আগের PIN
   দিয়ে লগইন করিয়ে নিশ্চিত করুন সব ঠিকমতো কাজ করছে।

কোনো নতুন Firebase Console সেটআপ (যেমন নতুন Auth provider) লাগবে না —
শুধু app.js আপলোড ও নতুন rules পাবলিশ করলেই হবে।
