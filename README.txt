XSS (৩ নং ঝুঁকি) সমাধান — app.js
================================

কী বদলেছে
---------
১. app.js-এর শুরুতে তিনটি নিরাপত্তা ফাংশন যোগ হয়েছে: esc(), jsq(), safeDataUrl()।
২. ডেটাবেস বা ব্যবহারকারীর লেখা যত জায়গায় স্ক্রিনে বসত (নাম, রোল, শ্রেণি, ছুটির কারণ, পরামর্শ,
   নোটিশ, ডায়েরি, পরীক্ষার নাম, বিষয়, ফি, শিক্ষকের ইমেইল, মাদ্রাসার নাম ইত্যাদি) সবখানে esc() লাগানো হয়েছে।
৩. onclick="...('আইডি')" জাতীয় জায়গায় jsq() লাগানো হয়েছে। এতে মাদ্রাসা আইডি বা পরীক্ষার নামের
   মধ্যে ' বা " লিখে বাটনের কোড ভেঙে স্ক্রিপ্ট চালানো যাবে না (সুপার অ্যাডমিন স্ক্রিন সহ)।
৪. ছবি/ফাইল/লোগোর লিংকে শুধু data: URL চলবে, javascript: চলবে না।
৫. ছুটির অবস্থা (status) শুধু pending/approved/rejected হলেই CSS class হিসেবে বসবে।

অ্যাপের কাজ, ডিজাইন বা ডেটা কিছুই বদলায়নি। ডেটাবেসে আগে থেকে থাকা লেখাও ঠিকভাবে দেখাবে।

কীভাবে বসাবেন
--------------
১. GitHub রিপোজিটরিতে পুরনো app.js মুছে/বদলে এই app.js আপলোড করুন (Add file → Upload files)।
২. যদি রিপোজিটরিতে sw.js (সার্ভিস ওয়ার্কার) থাকে এবং তাতে ক্যাশের ভার্সন নাম থাকে
   (যেমন CACHE_NAME = 'v12'), সেটার সংখ্যা এক বাড়িয়ে দিন। নইলে ফোনে পুরনো app.js চলতে পারে।
৩. অ্যাপ খুলে রিফ্রেশ করে দেখুন: উপস্থিতি, রেজাল্ট (মার্কশিট সেভ ও দেখা), নোটিশ, ডায়েরি, বেতন ঠিক চলছে কি না।

মনে রাখবেন
-----------
* এটা শুধু XSS ঠিক করে। আগের আলোচনার বাকি দুটি ঝুঁকি (৪ সংখ্যার PIN-এ চেষ্টার সীমা নেই,
  শিক্ষার্থীর তালিকা সব লগইনকারীর জন্য খোলা) এখনো আছে।
* firestore.rules আলাদা: আগের zip-এর ফাইলটাই বহাল, Firebase Console-এ Publish করা থাকতে হবে।
